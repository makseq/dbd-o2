# PHOTO_API.md — чего фотомодуль ждёт от остальной сборки

Пишется инженером фотомодуля для интегратора. Всё, что здесь описано, `photo2d.mjs`
**не реализует сам** — он это вызывает или получает снаружи.

Источники: `docs/ERRATA.md` F1–F3, `docs/PHOTO_PROCESSES.md` §7.

---

## 1. `SeparableSolver.solveHelmholtz(q, kappa, out)` — обязательный контракт

```js
/**
 * Решает  lap S - kappa^2 * S = -q   ТОЛЬКО в газовом зазоре, с eps = 1.
 * @param {Float64Array} q    длина nr*nz, раскладка [i*nz + j]. Ячейки вне газа
 *                            (j < JG0 || j > JG1) ИГНОРИРУЮТСЯ (диэлектрик для ВУФ непрозрачен).
 * @param {number} kappa      обратная длина поглощения, м^-1 (kappa > 0).
 * @param {Float64Array} out  длина nr*nz; заполняется S; вне газа обнуляется.
 * @returns {Float64Array}    out (или собственный буфер — модуль принимает оба варианта).
 */
solveHelmholtz(q, kappa, out)
```

Требования к реализации (ERRATA F3, PHOTO_PROCESSES §7.1–7.3) — **их нарушение
модуль обнаружить не может**, поэтому они выписаны явно:

1. **Отдельная сборка, `eps = 1`.** Матрицу Пуассона со сдвигом диагонали
   переиспользовать НЕЛЬЗЯ: Пуассон собран с `eps(z)` (`eps_r = 9` в барьерах,
   гармонические трансмиссивности на материальной границе), а фотонное уравнение
   имеет коэффициент 1 и живёт только в газе. Два разных конструктора.
2. **Переиспользуются** радиальная диагонализация (`K_r v_k = lambda_k M_r v_k`,
   `M_r = diag[(rf_{i+1}^2 - rf_i^2)/2]`, нормировка `v^T M_r v = I`, ERRATA B1),
   прогонка Томаса и инфраструктура прямого/обратного преобразования в метрике `M_r`.
3. **Знак модального уравнения** (ERRATA B3): `lambda_k` — собственные значения
   `-L_r`, то есть `lambda_k >= 0`, и модальное уравнение
   `d^2 S/dz^2 - (lambda_k + kappa^2) S = -q_hat` — с МИНУСОМ.
4. **ГУ на границах зазора по z — модальное открытое, НЕ `S = 0`:**
   `dS_hat/dn + sqrt(lambda_k + kappa^2) * S_hat = 0`.
   Дискретно — модификация только первого/последнего диагонального элемента:
   `b_first += sqrt(lambda_k + kappa^2)/dz_first`, `b_last += sqrt(...)/dz_last`.
   Однородный Дирихле занижает `S` у стенки на 30–60 % именно там, где идёт
   фотоэмиссия (VF5).
5. **По радиусу:** на оси Нейман заложен в `L_r` (`rf[0] = 0`, площадь грани нуль,
   `1/r` не вычислять — ERRATA B2); на `r = R` — Нейман (зеркальная стенка).
   `PHOTO_PROCESSES §7.3` предлагает открытое условие и на `r = R`, но оно делает
   радиальный оператор зависящим от собственного значения и **ломает разделимость**;
   для нашей зеркальной стенки Нейман к тому же физически корректен. Разница
   учтена: вклад зеркального изображения при `R = 0.5 мм` и `kappa >= 4.2e3`
   подавлен как `exp(-2*kappa*R) <= e^-4.2`.
6. **Факторизации кэшировать.** `kappa_j` (три штуки) и `lambda_k` постоянны,
   `eps` в газе не меняется → все `3 x nr` прогонок факторизуются один раз.
   Модуль вызывает `solveHelmholtz` до трёх раз за обновление, каждый шаг —
   кэш обязан переживать вызовы.

Проверка со стороны фотомодуля: тесты PH2 (спад `exp(-kR)/R`, < 2 %) и PH5
(баланс `INT q = kappa^2 INT S + уход через границу`, < 1 %) выполняются на
временной заглушке в `tests/photo.test.mjs`. **Ту же пару тестов надо прогнать на
настоящем `poisson2d.mjs`** — они ловят и знак сдвига, и метрику `M_r`, и ГУ.

## 2. Что модуль ждёт на входе `update(fields, opts)`

```js
photo.update({ ionizRate, powerDens }, { step });
```

| Поле | Единицы | Определение |
|---|---|---|
| `ionizRate` | м⁻³с⁻¹ | `S_ion = k_E1(|E|/N) * n_e * N` — реакция E1. **Модуль `|E|` обязателен** (ERRATA E1), иначе NaN на отрицательном полупериоде |
| `powerDens` | Вт/м³ | `P_dep = e * |Gamma_e · E|` — джоулев вклад электронов |
| `step` | — | номер шага, для `nPhotoSubstep` |

Оба массива — `Float64Array(nr*nz)`, раскладка `[i*nz + j]`. Модуль их не портит.
Фотоблок вызывается **после** Пуассона (нужно `E` для `P_dep`) и **до** источников
(PHOTO_PROCESSES §7.6).

## 3. Что модуль отдаёт и как это встраивать

| Выход | Единицы | Куда |
|---|---|---|
| `photoIonRate` (nr*nz) | м⁻³с⁻¹ | `dn_e/dt += S_pi`, `dn_O2p/dt += S_pi` — **одинаковый extent обоим** (ERRATA A5, заряд сохраняется тождественно) |
| `psi` (nr*nz) | фот·м⁻²с⁻¹ | поток прозрачных фотонов, диагностика |
| `nuPd.Om/.O2m/.O3m` (nr*nz) | с⁻¹ | `S_e += n_s*nu_s`, `S_s -= n_s*nu_s`; нейтральные продукты: `O⁻+hv→O+e` (`dn_O += ...`), `O₃⁻+hv→O₃+e` (`dn_O3 += ...`), `O₂⁻+hv→O₂+e` (фон) |
| `photoEmitFluxL/R` (nr) | эл·м⁻²с⁻¹ | **вычитается РОВНО ОДИН РАЗ**, внутри `Gamma_e,wall` |
| `gammaI` | — | использовать вместо `gamma_eff` при `photoEmission = true` |

### 3.1 Единственно правильное встраивание граничного члена (VF6)

```
Gamma_e,wall = 0.25*v_th_e*n_e + a*|mu_e*E|*n_e - gamma_i*Gamma_pos - Gamma_pe
dSigma/dt    = e*( Gamma_pos - Gamma_e,wall - Gamma_neg )
```

`Gamma_pe` входит **только** в `Gamma_e,wall`. Добавлять его отдельным слагаемым
в `dSigma/dt` нельзя — это двойной счёт, который тест VF6 (сохранение заряда
лучше 1e-10) обязан поймать.

### 3.2 Запрет двойного счёта по `gamma` (ERRATA F2, PHOTO_PROCESSES §3.7)

`gamma_eff = 0.02` из `PHYSICS.md` — **эффективный**: фотоэмиссия в него уже
свёрнута. Модуль считает

```
F_ph/F_i = Y_ph(hv_ref) * f_VUV * T_w * (e*U_b) / (gamma_eff * E_ph_ref)
gamma_i  = gamma_eff / (1 + F_ph/F_i)     -> photo.gammaI
```

и интегратор ОБЯЗАН брать ионный коэффициент из `photo.gammaI`, а не константу.
Тождество `gamma_i*Gamma_i + F_ph = gamma_eff*Gamma_i` проверяется тестом PH7.
При `photoEmission = false` модуль возвращает `gammaI === gammaEff` — деления нет,
потому что нет и отдельного фотонного члена.

## 4. Описание сетки, которое модуль ждёт от `solver2d.mjs`

```js
new PhotoModule(grid, params, solver)
grid = { nr, nz, rf /*nr+1*/, zf /*nz+1*/, JG0, JG1,
         rc?, dr?, Acell?, zc?, dz? }   // необязательные выводятся сами
```

`JG0 / JG1` — индексы первой и последней ГАЗОВОЙ строки (NUMERICS_2D §1.5).
Стенки — грани `zf[JG0]` (нижняя, `photoEmitFluxL`) и `zf[JG1+1]` (верхняя,
`photoEmitFluxR`). Раскладка полей `[i*nz + j]`, `z` — быстрый индекс.

## 5. Чего модуль НЕ делает (и делать не должен)

* не трогает `poisson2d.mjs`, `physics2d.mjs`, `solver2d.mjs`, `recorder.mjs`;
* не применяет источники к плотностям — только считает `S_pi`, `nu_pd`, `Gamma_pe`;
* не вычитает `Gamma_pe` из потока электронов (это делает солвер, ровно один раз);
* не реализует метастабильную эмиссию (PHOTO_PROCESSES §4: максимум 4.34 эВ против
  порога 9–10.5 эВ, вклад ≈ 0), фотодиссоциацию O₃ (§6.1, `2.7e-8` за 10 периодов)
  и фотодиссоциацию O₂ (§6.2, +0.88 % к выходу O — внутри погрешности E4).
