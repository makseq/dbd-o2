# PLOTS_API — контракт графиков и метрик плеера 2D-ДБР

Версия 1.0 · файлы: `player/js/plots.js`, `player/js/metrics.js`
Потребители: `player/index.html`, `player/js/app.js`, `player/js/scene.js` (пишет другой агент).
Источник данных: `player/js/loader.js` (`Playback`), формат — `sim2d/recorder.js`.

Демостраница: `player/plots-demo.html` (автономная, работает на `data/run-synth`).

---

## 0. Что нужно знать до интеграции (коротко и честно)

1. **`recorder.js` пишет в кадр только девять полей**: `n_e`, `ionizRate`, `rho`, `Emag`, `EN`,
   `photoIonRate`, `photoDetachRate`, `n_O3m`, `n_O3`. Из девяти сортов ТЗ в контейнере есть
   **три** (`e`, `O₃⁻`, `O₃`). `AxialProfilePlot` знает все девять, шесть недостающих рисует в
   легенде как `×` («сорт не записан в прогоне») и не строит. Дорисовывать их нечем и незачем.
2. **Столкновительное отлипание в контейнер не пишется вообще** — в `PhotoPanel` этот канал
   помечен `×`. Три фотоканала и ударная ионизация — есть.
3. **Сетка кадра — только газовый зазор** (`recorder` вырезает `jGas0..jGas1`), поэтому
   `grid.zFaces` идёт от 0.5 до 1.5 мм, а объёмные интегралы автоматически берутся по газу.
4. **Реальные прогоны обрываются на первом пробое (6–15 % периода)**, поэтому фигура Лиссажу у них
   не замкнута. `LissajousPlot` это обнаруживает и вешает бейдж; `C_cell` при этом извлекается
   верно (ветвь чисто ёмкостная), `C_diel` — нет. Так и показывается.
5. **«Ноль аллокаций в кадре» соблюдён для кода этих модулей**: буферы декимации, тики, подписи
   легенды, боксы hit-теста, шкалы — всё выделено заранее. Остаются две аллокации, навязанные
   чужим API и неустранимые в принципе: `ctx.measureText()` возвращает новый `TextMetrics`
   (вызывается только при пересборке легенды, не каждый кадр) и `Playback.getSurface()` делает
   `buf.slice()` внутри loader'а. Первое устранено кэшем, второе — на стороне loader'а.

## 2. Общий контракт классов графиков

Все графики строятся поверх одного каркаса:

| Член | Смысл |
|---|---|
| `new Klass(canvas, ...)` | `canvas` должен иметь CSS-размер (`width:100%;height:…`), внутренние `width/height` ставит сам класс |
| `.render()` | синхронная полная перерисовка (для «сейчас и точно») |
| `.requestRender()` | отложенная перерисовка через `requestAnimationFrame`, коалесцируется |
| `.setCursor(t)` | курсор времени, секунды; `NaN` — скрыть |
| `.destroy()` | отписка `ResizeObserver` и слушателей |
| `.canvas`, `.ctx` | доступны, но host их не трогает |

**Ретина.** Размер бэкстора = CSS-размер × `devicePixelRatio`, контекст масштабируется
`setTransform(dpr,0,0,dpr,0,0)`; вся геометрия внутри — в CSS-пикселях.

**ResizeObserver** повешен на сам canvas: host не обязан звать `resize()` руками.

**Тема** — тёмная, токены из `metrics.THEME` (значения обязаны совпадать с `UI_SPEC §3.1`).
Цвета продублированы числами, а не читаются из CSS-переменных: `getComputedStyle` в кадре — это
аллокация строки на каждый вызов.

**Лог-оси.** Значения `≤ 0` не проецируются (`Scale.to` даёт `NaN`), путь в этом месте рвётся,
а количество выпавших точек печатается подписью в углу. Ток в лог-режиме — это `|I|`, а знак
показан отдельной полосой у нижней кромки. Молчаливого выбрасывания половины данных нет нигде.

## 3. WaveformPlot

```js
const wf = new WaveformPlot(canvas, pb.series, {
  logCurrent: true,        // лог-ось тока (дефолт true)
  showUgap: true, showItot: true, showIcond: true,
  decades: 6,              // сколько декад показывать вниз от максимума
  onSeek: (t) => player.seek(t),   // клик по полю графика
});
wf.setWindow(t0, t1);      // окно времени, с
wf.setCursor(t);
wf.setLogCurrent(false);
wf.toggle('Ugap');         // вкл/выкл кривую
wf.timeAt(pxX);            // пиксель -> время
```

* Ряды берутся по именам из `series.names`: `Uapp`, `Ugap` (левая ось, кВ),
  `Icond`, `Itot` (правая ось, А/мА).
* **Декимация — min/max по пиксельным колонкам, не подвыборка.** Импульс 20 нс в окне 100 мкс
  остаётся видимым; при подвыборке он бы просто исчезал между отсчётами.
* **Результат декимации кэшируется** (`_prepare`, ключ = окно + ширина + набор кривых +
  лог/лин). Движение курсора пересчёта не вызывает. Это правка интегратора: на полных
  данных `run-default` ряд — 491 653 отсчёта, и без кэша один кадр стоил 72 мс
  (плеер шёл 13 fps при неподвижном кадре). Сама декимация не изменилась.
* Считывание значений в точке курсора печатается в правом верхнем углу.

## 4. LissajousPlot

```js
const lj = new LissajousPlot(canvas, pb.series, {
  freqHz: params.freqKHz * 1e3,
  geometry: { epsR, gapMM, dielMM, radiusMM },   // -> аналитика ёмкостей
  mode: 'period',          // 'period' | 'last8' | 'all'
  ghosts: 7,
});
lj.setCursor(t);
lj.setMode('last8');
const fit = lj.fit;        // результат фита текущего периода (кэшируется)
```

Область построения принудительно квадратная (1:1) — иначе наклоны читаются неверно.

Ломаная периода рисуется с **пиксельной** декимацией (точка, не сдвинувшаяся ни по одной
оси на полпикселя, в путь не добавляется; последняя точка ветви — всегда). Это правка
интегратора: на полных данных `run-default` один `render()` стоил **1020 мс** (1.3 fps),
после — ~6 мс. Фит считается по ПОЛНОМУ ряду и не затронут: на `run-synth` он даёт те же
`C_cell = 6.2587 фФ`, `C_diel = 69.14 фФ`, `R² = 0.997`, `W = 5.267 мкДж`.

### 4.1 Как извлекаются ёмкости

1. Локальные наклоны `dQ/dU` по соседним отсчётам; вес сегмента — его длина в нормированных
   координатах `(dU/ΔU, dQ/ΔQ)`. Вес `|dU|` был бы систематически несправедлив к разрядной ветви:
   она проходится почти при постоянном `U`.
2. **k-means по `log10` наклона**, 2 кластера, старт с 5/95 перцентилей. Аналитика в инициализацию
   не входит — фит остаётся независимой проверкой. В линейной метрике доминирующий кластер съедает
   второй (на `run-synth` линейный k-means давал `C_cell` ×7.8).
3. Каждый кластер делится на две ветви по знаку `dU/dt` → четыре стороны параллелограмма.
4. **Два разных оценщика, и это физика, а не лень:**
   * `C_cell` — взвешенная **медиана локального** `dQ/dU` ёмкостных сторон. Глобальный МНК по этой
     ветви даёт ерунду, когда за полупериод прошло много микроразрядов: ветвь превращается в
     лестницу, и прямая по её ступеням имеет наклон лестницы (≈ `C_diel`), а не ступени.
     Измерено: на `run-synth` (52 микроразряда за период) глобальный МНК давал **48 фФ вместо
     6.26 фФ** — ровно ошибка, о которой предупреждает `VALIDATION.md §V4b`.
   * `C_diel` — глобальный взвешенный МНК по разрядным сторонам: здесь нужен наклон огибающей.
5. Вершины A…D — пересечения соседних сторон; `ΔQ` — размах `Q` по разрядной ветви между вершинами.
6. `W = ∮U dQ` считается **численно по данным** (трапеции), не по фиту; `P = W/T`.
   `U_min` — обращение формулы Мэнли `W = 4·C_diel·U_min·(U₀ − U_min)`, помечен как производная
   величина; при отрицательном дискриминанте возвращается `null`, а не выдуманное число.

### 4.2 Сверка с аналитикой (обязательная)

`analyticCapacitances({epsR, gapMM, dielMM, radiusMM})` из `metrics.js` даёт
`C_diel = ε₀ε_r A/(d₁+d₂)`, `C_gas = ε₀A/d_gap`, `C_cell = C_d‖C_g`, где `A = πR²`,
плюс `perCm2` — те же ёмкости на 1 см² для сверки с каноническими числами `ERRATA §C V4`:

| | на 1 см² | на ячейку `πR²`, R = 0.5 мм |
|---|---|---|
| `C_diel` | **7.969 пФ** | 62.59 фФ |
| `C_gas` | 0.885 пФ | 6.95 фФ |
| `C_cell` | **0.797 пФ** | **6.259 фФ** |

Панель печатает `fit`, `аналитика` и расхождение в процентах, покрашенное по порогам
(`|Δ| > 4 %` — жёлтый, `> 25 %` — красный; 4 % — это допуск `NUMERICS_2D §7.5 V4`).

Проверено на данных:

| прогон | `C_cell` фит | Δ | `C_diel` фит | Δ | вердикт |
|---|---|---|---|---|---|
| `run-synth`, период 1 | 6.26 фФ | **0.0 %** | 69.1 фФ | +10.4 % | R² = 0.997, петля замкнута (0.09 %) |
| `run-default` (обрыв на 8.3 мкс) | 6.27 фФ | +0.2 % | 836 фФ | +1236 % | бейдж: петля не замкнута, R² = 0.33, сторон < 4 |

### 4.3 Поля результата `fit`

```
{ ok, C_cell, C_diel, sides[4], vertices[4], W, P, dQ, Umin,
  r2min,       // min R² РАЗРЯДНЫХ сторон (у ёмкостных R² не показатель — см. 4.1)
  cellSpread,  // разброс свободного члена ёмкостной ветви, доля от ΔQ
  clusterSep,  // во сколько раз разделены кластеры наклонов
  closure,     // (Q_end − Q_start)/ΔQ — незамыкание петли
  warn,        // блокирующая формулировка или null
  note }       // информационная (дробление ветви микроразрядами) или null
```

`warn ≠ null` → на графике бейдж `#fab219`. Правило: **молча выдать `C_diel` по кривой петле хуже,
чем не выдать вовсе** (`UI_SPEC §2.3`).

## 5. RadialProfilePlot

```js
const rp = new RadialProfilePlot(canvas, { scale: 'lin' }); // 'lin' | 'asinh'
const s = pb.getSurface(frameIndex);       // {sigmaL, sigmaR}, Кл/м²
rp.setData(pb.grid.rCenters, s.sigmaL, s.sigmaR);
```

* `setData` хранит **ссылки**, не копии — host обязан не переиспользовать буфер под другой кадр
  до следующего `setData`.
* Ось Y — нКл/см² (`1 Кл/м² = 10⁵ нКл/см²`). Верхняя граница сглажена по кадрам (спад 8 % за кадр),
  чтобы шкала не мерцала.
* `scale:'asinh'` — знаковая «лог-подобная» ось: линейна у нуля, логарифмична на хвостах,
  ноль отображается точно.

## 6. AxialProfilePlot

```js
const ap = new AxialProfilePlot(canvas, { minDecades: 6, floor: 1e10 });
updateAxialFromPlayback(ap, pb, frameIndex, { mode: 'axis' });  // 'axis' | 'mean'
```

* `mode:'axis'` — столбец `i = 0` (ось симметрии), `'mean'` — среднее по `r` с весом объёма
  (передайте `vol` из `cellVolumes(pb.grid)`, иначе среднее будет невзвешенным).
* Ручной путь: `ap.setZ(pb.grid.zCenters)` + `ap.setSpecies(key, Float32Array|null)`.
* Легенда кликабельна: **клик — solo, alt+клик — скрыть**, `×` — сорт не записан в прогоне.
* Идентичность кривой кодируется цветом **и** штрихом **и** прямой подписью у правого конца
  (`UI_SPEC §3.2`: одним цветом кодировать нельзя).
* Цвета 1–6 — валидированная палитра `UI_SPEC §3.2`. `O₄⁺ #ff8b3d`, `O₃⁻ #45b8c9`, `O₂(a) #b0b8c4`
  добавлены сверх неё и через `validate_palette.js` **не проходили** — для них штрих и подпись
  обязательны вдвойне.

`SPECIES` — реестр: `{key, field, label, color, dash, width}` для e, O₂⁺, O₄⁺, O⁻, O₂⁻, O₃⁻, O, O₃, O₂(a).

## 7. PhotoPanel

```js
const vol = cellVolumes(pb.grid);                       // м³, один раз
const photo = await PhotoSeriesBuilder.build(pb, { onProgress });
const pp = new PhotoPanel(canvas, { decades: 12 });
pp.setData(photo);
pp.setWindow(t0, t1);
pp.setCursor(t);
```

* `PhotoSeriesBuilder.build` **однократно** (при загрузке прогона, не в кадре) интегрирует по объёму
  газа `photoIonRate`, `photoDetachRate`, `ionizRate` и берёт `photoEmitTotalL + photoEmitTotalR`
  из `series` (это уже полный поток с поверхности, эл./с). Возвращает
  `{ t: Float64Array, chan: {ключ: Float32Array}, missing: string[] }`.
  Между чанками отдаёт управление через `setTimeout(0)` — UI не блокируется.
* Ось Y — темп, событий/с по всему объёму газа, логарифмическая, 12 декад.
* Панель печатает `S_ph/S_imp` в точке курсора. В этом её смысл: фотопроцессы почти всегда на
  3–6 порядков слабее ударной ионизации **по темпу** и при этом определяют, где и когда зародится
  филамент. Панель показывает разрыв в темпе, а не прячет его.
* `CHANNELS` — реестр каналов; `collDetach` всегда `missing` (в контейнере нет).

Контрольные числа (кадр №195 `run-synth-compact`): `V_gas = 7.8540e-10 м³` (аналитика `πR²d_gap`
до пятого знака), ударная ионизация `1.58e16 с⁻¹`, фотоионизация `1.18e15 с⁻¹`,
фотоотлипание `1.34e10 с⁻¹`.

## 8. MetricsPanel

```js
const mp = new MetricsPanel(document.querySelector('#metrics'), {
  tiles: DEFAULT_TILES,     // 9 плиток UI_SPEC §2.5
  sparkLen: 96,
});
mp.update({
  power: 0.0527, maxEN: 2461, ozone: 1240,
  C_cell: fit.C_cell, C_diel: fit.C_diel, energy: fit.W,
  Ipeak: 0.21, breakdowns: 2, specEnergy: { v: 283, note: 'накопл./V_gas' },
  _status: { dt: 3.5e-11, frame: '128/391', cfl: 0.31, residual: 3e-11, limiter: 'diff' },
});
```

* Значение: `number | null | {v, note, status}`. `null`/`NaN` → «—» и плитка приглушается.
* Ключ, отсутствующий в объекте, **не трогается** — панель обновляется частями.
* Строка статуса красится по порогам (`CFL > 0.9`, `residual > 1e-8` — жёлтый и далее).
* Свои стили модуль инжектит один раз под префиксом `.mp-`; `css/app.css` не трогается.
* Строки пишутся только при фактическом изменении (никакого мельтешения и лишних reflow).
  Рекомендуемая частота вызова `update()` — 4 Гц (`UI_SPEC §4.1`), кроме `Ipeak` (по событию).

### Форматирование

| Функция | Пример |
|---|---|
| `fmtSI(6.2587e-15, 'F')` | `6.26 fF` |
| `fmtSI(0.21, 'A')` | `210 mA` |
| `fmtExp(1.62e23, 'm⁻³')` | `1.62e+23 m⁻³` |
| `fmtFixed(2461, 0, 'Td')` | `2 461 Td` |
| `fmtTime(8.2984e-6)` | `8.2984 µs` |
| `fmtPct(-0.45)` | `−0.5 %` |
| `fmtPow10(21)` | `10²¹` |

Все — без исключений на `null`/`NaN`/`Infinity` (возвращают `—`), минус — типографский `−`,
тысячи разделены тонким пробелом, всё пригодно для `font-variant-numeric: tabular-nums`.

## 9. Рекомендуемая склейка в app.js

```js
const pb = await Playback.load('../data/run-default-compact/');
const P = pb.manifest.params;
const vol = cellVolumes(pb.grid);

const wf = new WaveformPlot(cvWave, pb.series, { onSeek: seek });
const lj = new LissajousPlot(cvLiss, pb.series, {
  freqHz: P.freqKHz * 1e3,
  geometry: { epsR: P.epsR, gapMM: P.gapMM, dielMM: P.dielMM, radiusMM: P.radiusMM },
});
const rp = new RadialProfilePlot(cvRad);
const ap = new AxialProfilePlot(cvAx);
const pp = new PhotoPanel(cvPhoto);
const mp = new MetricsPanel(elMetrics);
PhotoSeriesBuilder.build(pb).then((d) => pp.setData(d));

function onFrame(t) {                       // вызывается из плеера
  const i = pb.findFrame(t);
  wf.setCursor(t); lj.setCursor(t); pp.setCursor(t);
  const s = pb.getSurface(i);
  rp.setData(pb.grid.rCenters, s.sigmaL, s.sigmaR);
  updateAxialFromPlayback(ap, pb, i, { mode: 'axis', vol });
  wf.render(); lj.render(); rp.render(); ap.render(); pp.render();
}
```

`setCursor/setData` уже дёргают `requestRender()`, так что явные `render()` нужны только если
host хочет строго синхронную отрисовку в своём кадре.

## 9а. Ловушка контейнера: кадры могут кончиться раньше рядов

В `run-synth` бюджет кадров (`maxFrames = 391`) исчерпывается на **13.9 мкс**, а `series.bin`
идёт все два периода (200 мкс). То есть `pb.frameTimes[last] ≪ pb.series.t[last]`.

Из этого следует для host'а:
* курсор времени должен ходить по диапазону **рядов** (иначе три четверти данных недостижимы);
* `WaveformPlot`/`LissajousPlot` работают на рядах и покрывают весь прогон;
* `PhotoPanel` живёт только там, где есть кадры — окно ставьте по `frameTimes`;
* поля (`σ`, профили) после последнего кадра **замораживаются**, и это надо подписать явно.
  В `plots-demo.html` так и сделано: `⚠ кадры кончились на 13.915 µs — поля заморожены, ряды идут дальше`.

## 9б. Что проверено в браузере (headless Chromium, `plots-demo.html`)
